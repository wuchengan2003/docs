---
title: "Run an experiment"
---

`eval run` submits an evaluation experiment: it selects one evaluation dataset version, one or more evaluator versions, and evaluates a specific version of the target. The command resolves the evaluation backend from the current account; on the TEA backend, `--dataset-version`, `--evaluator-version`, `--target-type`, and `--target-version` let you pin the exact resources.

```bash
agentkit eval run \
  --dataset qa-set \
  --dataset-version 0.0.8 \
  --evaluator relevance \
  --evaluator-version 0.1.2 \
  --target qa-agent \
  --target-version 1.0.0
```

## eval backend

Show and refresh the evaluation backend resolved for the current account. The result is written to a local cache and reused by subsequent `eval` subcommands.

| Flag / Argument | Description | Default |
| --- | --- | --- |
| `--json` | Output raw JSON. | `false` |

```bash
agentkit eval backend
agentkit eval backend --json
```

Backend resolution uses the current login state and environment variables. To force a cache refresh or debug requests, put the debug flag after `eval` and before the subcommand:

| Flag / Argument | Description | Default |
| --- | --- | --- |
| `--cache-refresh` | Ignore the local cache and fetch fresh backend information. | `false` |
| `--verbose` | Print full TEA requests to stderr with sensitive cookies masked. | `false` |

```bash
agentkit eval --cache-refresh backend
agentkit eval --verbose run --dataset qa-set --evaluator relevance --target qa-agent --dry-run
```

## eval run

| Flag / Argument | Description | Default |
| --- | --- | --- |
| `--dataset <id\|name>` | Evaluation dataset ID or exact name. Required. | None |
| `--dataset-version <id\|name>` | TEA dataset version ID or exact version string, for example `0.0.1`. If omitted, the current version is used. | Current version |
| `--evaluator <id\|name>` | Evaluator ID or name. Required and repeatable. | None |
| `--evaluator-version <id\|name>` | TEA evaluator version ID or exact version string. Repeatable, and should align one-to-one with `--evaluator`. | Current version |
| `--target <runtime name\|id>` | Runtime or eval target to evaluate. Required. | None |
| `--target-type <n>` | TEA Source Eval Target type. | `101` |
| `--target-version <version>` | TEA Source Eval Target version. If omitted, the latest version from the version list is used. | Latest version |
| `--name <name>` | Experiment name. | `<dataset>-<timestamp>` |
| `--description <text>` | Experiment description. | None |
| `--concurrency <n>` | Number of cases to run concurrently; must be a positive integer. | `5` |
| `--map <spec>` | Override field mapping. Repeatable. TEA and Coze backends use different syntax; see below. | Automatic mapping |
| `--dry-run` | Print the request that would be submitted without starting an experiment. | `false` |
| `-p, --project <name>` | Project name; ignored by the TEA backend. | `default` |
| `--json` | Output raw JSON. | `false` |

```bash
agentkit eval run --dataset qa-set --evaluator relevance --target qa-agent --dry-run
```

<Note>
The TEA backend requires a concrete version for each evaluator. If you omit `--evaluator-version`, the CLI resolves the evaluator's current version; when you pass multiple evaluators, pass the same number of `--evaluator-version` values in the same order.
</Note>

## Field mapping

An experiment has three layers of data to align: dataset fields, target input and output, and evaluator inputs. By default, the CLI passes the dataset's primary input to the target input and passes the target output to the evaluator answer field. Use `--map` when field names differ.

The TEA backend uses arrow syntax:

| Form | Meaning |
| --- | --- |
| `evaluator.<slot> <- dataset.<col>` | Evaluator input field comes from a dataset field. |
| `evaluator.<slot> <- target.<field>` | Evaluator input field comes from a target output field. |
| `target.<slot> <- dataset.<col>` | Target input field comes from a dataset field. |

```bash
agentkit eval run \
  --dataset qa-set \
  --dataset-version 0.0.8 \
  --evaluator relevance \
  --evaluator-version 0.1.2 \
  --target qa-agent \
  --map "target.user_input <- dataset.question" \
  --map "evaluator.input <- dataset.question" \
  --map "evaluator.reference_output <- dataset.answer" \
  --map "evaluator.output <- target.actual_output"
```

The Coze backend keeps the equals-sign syntax:

| Form | Meaning |
| --- | --- |
| `evaluatorField=datasetField` | Evaluator input comes from a dataset field. |
| `evaluatorField=target:targetOutput` | Evaluator input comes from a target output field. |
| `target:targetInput=datasetField` | Target input comes from a dataset field. |

```bash
agentkit eval run --dataset qa-set --evaluator relevance --target qa-agent \
  --map "output=target:actual_output" \
  --map "target:user_input=question"
```

## Check before submitting

For the first run, add `--dry-run` to confirm the resolved dataset version, evaluator versions, target version, and field mapping:

```bash
agentkit eval run \
  --dataset qa-set \
  --dataset-version 0.0.8 \
  --evaluator relevance \
  --evaluator-version 0.1.2 \
  --target qa-agent \
  --target-version 1.0.0 \
  --dry-run \
  --json
```

After a successful submission, the command returns an experiment ID. Track it with [`eval experiment show`](/productions/agentkit-cli/preview/en/commands/eval/experiment), or inspect results with [`eval experiment results`](/productions/agentkit-cli/preview/en/commands/eval/experiment).
