---
title: "Invoke a runtime"
---

The `invoke` command group sends requests to a deployed Runtime. The regular entry point is `agentkit invoke run`: it can resolve a Runtime from `agentkit.yaml`, or invoke directly by Runtime ID or endpoint URL.

## invoke run

Send a message or JSON payload to a Runtime. By default, the command uses the Python SDK-compatible request shape and prints answer text from streaming responses; pass `--raw` to inspect raw streaming events or JSON responses.

| Flag / Argument | Description | Default |
| --- | --- | --- |
| `[message]` | User message to send; required unless `--payload` is provided. | None |
| `--config-file <path>` | Config file used to resolve the Runtime. Cannot be used with `--runtime-id` or `--endpoint`. | `agentkit.yaml` |
| `-p, --payload <json>` | JSON request payload. Cannot be used with `[message]`. | None |
| `-h, --headers <json>` | Extra request headers as a JSON object. | None |
| `-r, --runtime-id <id>` | Resolve endpoint and auth by Runtime ID. | None |
| `-e, --endpoint <url>` | Invoke a specific endpoint URL directly; must be used with `--apikey` or an `Authorization` header in `--headers`. | None |
| `--region <region>` | Region used for Runtime ID lookup; only valid with `--runtime-id`. | Auto-detect |
| `--a2a` | Force an A2A JSON-RPC request in direct mode. | `false` |
| `--show-reasoning` | Show LangChain `reasoning_content` in streaming output. | `false` |
| `--raw` | Print raw streaming events or the raw JSON response. | `false` |
| `--apikey <key>` | API key for authentication; used as a bearer key in direct endpoint mode. | None |

```bash
agentkit invoke run "Hello, introduce yourself"

agentkit invoke run \
  --runtime-id r-xxxxxxxx \
  --region cn-beijing \
  "Summarize this session"

agentkit invoke run \
  --endpoint https://runtime.example.com/run_sse \
  --apikey "$AGENTKIT_RUNTIME_API_KEY" \
  --payload '{"prompt":"Generate three test cases"}' \
  --raw
```

Direct endpoint mode does not read `agentkit.yaml`. With `--runtime-id`, the CLI resolves the Runtime endpoint and default auth information, so `--endpoint` cannot be passed at the same time and `--apikey` cannot override the `key_auth` credential resolved from the Runtime ID.
